# Purpose

This document defines the authorization system for Strike IQ.

Authorization determines what an authenticated user is allowed to access and perform.

Authentication verifies identity.

Authorization verifies permissions.

Authorization must always be enforced on the server.

---

# Authorization Principles

The authorization system must follow these principles.

- Deny by default.
- Grant only required permissions.
- Never trust client-side role checks.
- Validate permissions on every protected request.
- Keep business rules centralized.
- Avoid duplicate permission logic.

---

# Authorization Model

Strike IQ uses Role-Based Access Control (RBAC) with subscription-based feature gating.

Role determines administrative capabilities.

Subscription determines premium feature access.

These are independent systems.

---

# User Roles

## Guest

Description

Unauthenticated visitor.

Permissions

- View marketing website
- View pricing
- View FAQs
- Register
- Login

Restrictions

- No dashboard access
- No prediction access
- No billing access

---

## User

Description

Authenticated user without an active premium subscription.

Permissions

- Dashboard
- View free predictions
- Save predictions
- Update profile
- Manage account

Restrictions

- Premium predictions
- Admin features

---

## Premium

Description

Authenticated user with an active subscription.

Permissions

Everything available to User plus:

- Premium predictions
- Advanced AI explanations
- Historical performance
- Premium analytics

Restrictions

- No administration

---

## Admin

Description

Platform administrator.

Permissions

- Manage matches
- Generate predictions
- Publish predictions
- Archive predictions
- Manage users
- View analytics
- Manage subscriptions

Restrictions

Cannot change Super Admin accounts.

---

## Super Admin

Description

Platform owner.

Permissions

Full system access.

Additional Permissions

- Manage administrators
- System configuration
- Platform settings
- Security settings
- Audit logs
- Feature flags

---

# Subscription Levels

Subscription is separate from role.

Available plans

- Free
- Premium Monthly
- Premium Yearly

A Premium subscription unlocks premium features without changing the user's role.

# Server Authorization Rules

Every protected Server Action must:

1. Validate session.
2. Retrieve authenticated user.
3. Validate role.
4. Validate subscription (if required).
5. Validate resource ownership.
6. Execute business logic.
7. Log action.

---

# Resource Ownership

Users may only modify resources they own.

Examples

Users may:

- Edit their own profile.
- Save their own predictions.
- Manage their own subscription.

Users may not:

- Modify another user's account.
- Cancel another user's subscription.
- View another user's billing history.

Administrators may override ownership only when required by platform operations.

---

# Premium Feature Gating

Premium functionality must be checked on the server.

Never rely on hidden buttons or disabled UI.

Example flow

```
User Request

↓

Validate Session

↓

Retrieve Subscription

↓

Subscription Active?

↓

Yes → Continue

↓

No → Return Upgrade Required
```

---

# Middleware Responsibilities

Middleware should:

- Protect authenticated routes.
- Redirect unauthenticated users.
- Redirect unauthorized users.
- Prevent Guests from accessing dashboard pages.

Middleware should not contain business logic.

---

# Audit Requirements

The following actions must create audit records.

- User role changed
- Subscription changed
- Prediction published
- Match created
- Match deleted
- User suspended
- User restored
- Admin login
- System configuration changed

Audit records are immutable.

# Error Responses

Unauthorized

HTTP 401

```json
{
  "success": false,
  "error": {
    "code": "UNAUTHENTICATED",
    "message": "Authentication required."
  }
}
```

Forbidden

HTTP 403

```json
{
  "success": false,
  "error": {
    "code": "FORBIDDEN",
    "message": "You do not have permission to perform this action."
  }
}
```

Premium Required

HTTP 402 or 403 (project decision)

```json
{
  "success": false,
  "error": {
    "code": "PREMIUM_REQUIRED",
    "message": "Upgrade your subscription to access this feature."
  }
}
```

# Authorization Testing

The following scenarios must be tested.

Guest

- Cannot access dashboard.

User

- Cannot access premium pages.
- Cannot access admin routes.

Premium

- Can access premium content.
- Cannot access admin routes.

Admin

- Can manage platform resources.
- Cannot access Super Admin settings.

Super Admin

- Full access.

---

# Success Criteria

Authorization is complete when:

- Every protected route validates permissions.
- Every Server Action validates authorization.
- Premium features are enforced server-side.
- Resource ownership is respected.
- Audit logs capture privileged actions.
- Unauthorized access is denied consistently.
